# Profile continuation evidence

The authority is `Integrity.ProfilePartitionLaws`. Its equations cover actual
CHAIN and STREAM update reindexing, append composition with arbitrary successful
fuel, settled empty updates, and successful update/finalization uniqueness.
The proofs compare actual engine continuations; they do not posit equal digests
or an independent implementation of the frame codec.

Successful source updates on a byte sequence and its partitions reach the same
profile state under the stated successful-continuation premises. A consumer can
therefore compose actual singleton updates into a canonical profile driver
without assuming that emitted bytes already equal its answer. Proving sufficient
fuel for the fixed canonical drivers is a distinct obligation. These equations
do not alone extract the segments from every owned execution, establish output
image preservation or prove the standard SHA algorithm against FIPS.

generated-module compilation, exact axiom audits and leanchecker. The actual
StreamEngine defect advancing its consuming input offset by two invalidates the
reindex/append proofs. Exact restoration reproduces the same attestation. Exact
source, fifteen dependency-model identities, diagnostics and signatures are
recorded under `validation/integrity/profile-partition`.

The scope uses the saved language-1.2 SDK/compiler and recorded official
schema-only authoring normalization. It does not qualify the unchanged original
product lock, the Core preservation closure, native/Wasm production targets or
the full archive product. Both existing format identities retain their meaning.

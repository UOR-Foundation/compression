# Owned linear observation and template handoff

Behavior is source-owned by `OwnedLinearFit`, `OwnedLinearFitControls`,
`FittedTemplate` and `FittedTemplateControls`. This note records their current
composition boundary, not acceptance authority.

## Actual input path

The observer retains exactly one Arena. Existing `Wire.OwnedRead` navigates the
retained caller input sequence and returns borrowed image spans. The caller's
actual input root ticket remains in the observer inventory throughout every
read. A borrowed span adds no ticket. Actual `Core.RuntimeImage.validateSpan`
and `readSpanByte` validate/access the backing; no producer parameters, cached
original-output claim or copied whole-input literal supplies observations.

The fixed fitting/reader state is backed by a real 4096-byte control reservation.
Preparation validates the existing resource scope, then allocates it. Each
public funded step pays at most its current operation and returns excess.
Navigation, getter, fitting and owner-installation tasks have explicit shared
RuntimeWork fees, committed before executing their operation. Partial deposits
cannot traverse, read or update the model. Matching RuntimeImage Cost roots
quote a separate logical dispatch count before success or typed error. These
quotes are not CPU, allocator or decoder-semantic units.

Typed failures retain their actual Arena, input/search/control owners,
prepaid-credit prefix, usage and observation state. Work refusal does not call
the getter. Count/address inability is operational, not a semantic input cap
or a certificate-predecessor exclusion. Ready means model observation completed,
not that any candidate reconstructed the input or beat raw storage.

At completion the fitting control is installed under caller.search, preserving
any original search ticket through the registered owner aggregate. The explicit
FittedTemplate handoff moves the one owning carrier into the existing
TemplateOwner and retains fixed History metadata without an Arena. It preserves
all resource and funding/reader/getter/fitting counters rather than resetting
preprocessing work. History binds the actual fitting-owner, original search and
input handles. The actual fitting reservation remains owned through downstream
candidate preparation. The consuming run controller must move, not duplicate,
these carriers and keep metadata custody represented through later ownership
transfers.

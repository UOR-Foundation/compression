# Runtime machine diagnostics

The `.lex.tex` scenario definitions own expected behavior. `run.py` invokes the
official compiler, compiles its generated Lean modules with the selected Lean
binary, and asserts every named helper control. It contains no decoder,
reference evaluator, arithmetic implementation or compiler substitute.

Pass explicit paths to an isolated language-1.2 diagnostic project, the official
LexLean and Lean binaries, and `LexLeanRuntime` modules generated by the same
SDK's runtime-library project. The diagnostic project must contain the exact
machine source and its committed computational dependencies. The repository's
mixed language-1.1 authority and immutable SDK locks are not rewritten by this
driver. Main-project migration and full `just vv` remain the qualification
owner's responsibility.

```
python tests/runtime-machine/run.py \
  --project <prepared-diagnostic-project> \
  --lexlean <official-lexlean-binary> --lean <selected-lean-binary> \
  --runtime-modules <official-generated-modules/LexLeanRuntime> \
  --report <diagnostic-report.json>
```

The report is explicitly scoped and always has `implementationAccepted=false`.
Every helper scenario is required; there is no skip/filter/ignore option. The
process fails for missing roots, compilation failure, false/missing/extra
observations, nonzero execution, or source changes during the run. This is Lean
VM execution of actual generated source, distinct from certified Rust export,
physical native measurements, general refinement or release acceptance.

The 39 dispatch controls observe prepared actions. Actual end-to-end machine
operations are owned separately by `RuntimeMachineEngineTests.lex.tex`. Neither
scope can silently stand in for the other.

`EngineRun.lean` imports and asserts the entire typed engine scenario aggregate.
After compiling the generated dependency closure, run it with the same selected
Lean binary and LEAN_PATH pointing to the generated modules. It has no scenario
filter. `evidence/engine.json` records the exact 68-case aggregate and inputs;
`evidence/helpers.json` records the separate twelve helper groups. The isolated
mixed-version diagnostic projection is described in
`docs/implementation/runtime-machine.md`; these receipts do not silently qualify
its unmodified dependency theorem proofs or a product export.

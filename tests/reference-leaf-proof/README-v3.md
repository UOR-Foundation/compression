## Exact generic rule and pinned support

For a theorem, collect all non-nullary constructors of checked document
inductives in directly imported modules, and in local declarations preceding
the theorem. Use the ordinary elaborated declarations for model-derived data.
Resolve each module through the existing checked Lean import/name mappings
(including package imports), not by assuming one project prefix for every
import. Emit each constructor's fully qualified Lean name followed by `injEq`,
escaping every segment and sorting the resulting names. Keep the already-existing
`Option.some.injEq` bridge first. Do not add future declarations, nullary
constructors, arbitrary native-core names, arbitrary simp lemmas, or unimported
modules. This changes no accepted input types, terms, theorem domains, or data
representations. It is a deterministic proof-normalization rule over the
compiler's already checked data declarations, not a new source restriction.

Pinned [Lean v4.32.1 Injective.lean](https://github.com/leanprover/lean4/blob/v4.32.1/src/Lean/Meta/Injective.lean)
names this theorem `ctorName ++ injEq` in `mkInjectiveEqTheoremNameFor` and exports
it for public constructors. Its general generation conditions matter: the
inductive must be safe and not a predicate, `genInjectivity` must be enabled
(default true), the constructor must have fields, and the equation set after
omitting proof-irrelevant fields must be nonempty. The checked ordinary
LexLean document inductives here are public nonindexed data types; value
parameters are forbidden and constructor fields are ordinary `SemanticType`
data types. Hence their non-nullary constructors supply the named rules. This
argument must not be generalized to arbitrary native-core inductives.

The second v2 step is already generic: pinned [Contradiction.lean](https://github.com/leanprover/lean4/blob/v4.32.1/src/Lean/Meta/Tactic/Contradiction.lean)
uses `mkNoConfusion` on equalities of different constructors. Keep its stock
configuration. No search/resource setting is increased.

## Bounded recommendation

Qualify this finite metadata-whitelist variant next. If it succeeds, it supports
proposing a generic PF-21 enhancement for independent upstream review and
regressions; it still does not authorize or establish that enhancement. If it
fails, inspect its exact goals before revising anything.

Stock [injections](https://github.com/leanprover/lean4/blob/v4.32.1/src/Lean/Meta/Tactic/Injection.lean)
is an alternative generic no-confusion mechanism, but changes the successful
proof shape, only processes hypothesis equations, needs post-split rewriting
first and possibly afterward, and has a stock recursion depth of 5. It is not
needed for this closest-to-v2 experiment. The builtin reduceCtorEq simproc only
handles different constructor heads and cannot replace same-head injectivity.
